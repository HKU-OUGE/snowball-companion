# 电脑插件与设备更新

## v0.6.2：语音发起任务的开始状态

通过桌面应用接口发送的语音文字可能没有触发 `UserPromptSubmit`，直到后续
工具执行才出现 Hook。现在沿用已有的本机会话文件索引，增量读取明确的根回合
`task_started`、`task_complete` 和 `turn_aborted` 元数据，补齐开始、结束状态。
消息送达回执、会话存在、正文和推理内容都不能据此生成工作状态。

新的回合事件只有比原 Hook 状态新时才参与显示；后来的详细 Hook 状态优先。
原始 Hook 序号和记录保留，未回答的问题继续提醒。事件重复读取不延长任务
有效期，新的开始事件也会撤销先前的自动安装空闲依据。Windows 与 Linux 使用
同一元数据路径。已有设备无需为这项同步修复刷固件；加载新版电脑 Hub 即生效。

## v0.6.1：新任务状态优先同步

Codex 电脑桥接在会话列表、问题选项、长摘要的分包之间重新检查真实状态，
新任务不必等待整个发送循环结束。所有写入仍经过同一个串行通道，插入状态后
重新获取认证序列；会话优先级、问题处理和有效期规则保持一致。
同一连接最多复用 200 毫秒内的已认证 INFO 读取，任意写入或写入失败立即失效；
等待设备应用回执时不复用尚未应用的结果。Wi-Fi 的认证轮询行为保留。

本次为电脑插件修复，已有兼容设备无需刷固件。升级后需要让已运行的共享桥接
加载新代码；先确认没有固件传输或语音上传，再通过对应系统的后台服务管理器
重启桥接，保留 Hub、配对、Wi-Fi 和设备资源。Windows 使用
`windows-services.ps1`，不能套用 Linux 服务命令。源码、安装包、本机运行时与
SD 安装盘是独立交付对象，升级源码不会自动替换其他副本。

## v0.5.8 本地候选：小文件优先 SD，大文件优先网络

插件包与安装说明优先从 SD 获取；资源先复用电脑缓存，其余不超过 1 MiB 的文件优先 SD，模型、Python 与大依赖优先联网，失败后回退 SD。网络支持续传和固定哈希校验，持续有数据的下载不设置总时限。SD 导入边复制边校验，连接/语音依赖按步骤分组，减少首次准备的读取量。网页显示当前来源，Skill 和入门指南使用同一规则。

Codex 候选为 0.5.8；Claude/Cursor 适配器仍为 0.2.4，随包控制台更新为 0.5.8。旧控制台仅在已验证归属且空闲时重载，不重启 Hub、蓝牙桥接或正在执行的配置任务。此条记录为本地源码和候选包，GitHub Release、已安装插件注册和 SD 安装盘须分别更新，不能由构建成功推断已发布或部署。

## v0.5.7：网页自动配置与轻量语音

Skill 打开控制台后自动准备连接环境、当前用户登录自启动、连接服务、本地语音与账号 Pet。所有选择、进度、重试和跳过集中在网页；账号 Pet 必须由 agent 经真实 Pets 接口核验。已有服务、模型与配对复用，普通打开页面不自动安装。Windows 使用原生计划任务及进程归属检查；Linux 使用用户服务；macOS 自启显示不适用。

新用户默认多语言 Base（约 148 MB），可选 Tiny（约 78 MB）或 Small（约 486 MB），已有 Small 不自动降级。挂载 SD 后优先校验并导入对应模型和系统依赖到电脑缓存；依赖按 Windows x64、Linux x64、Apple Silicon Mac、Intel Mac 以及 Python 3.12 / 3.13 区分。提供独立 Python 3.13.18 作为缺少完整解释器时的准备资源。原有语音模型与录音投递功能保持独立检查，系统驱动和 AI 软件授权仍需单独完成。详见 [SD 离线资源](../codex/docs/OFFLINE-RESOURCES.md)。

Codex 插件版本 0.5.7，Claude/Cursor 适配器版本 0.2.4。本次插件包不包含模型、设备固件、个人凭据或 SD 资源，也不会自动刷机。整卡 USB 存储需要对应固件。

## 更新电脑插件

从 [Releases](https://github.com/HKU-OUGE/snowball-companion/releases) 核对版本和下载资产，并验证 SHA-256。发布页没有资产时，源码或本地 ZIP 不能当作已发布版本。

沿用 [安装与卸载](INSTALLATION.md) 中本平台的升级流程。先确认服务实际运行目录，不用旧包覆盖较新的共享运行时，不启动第二个 Hub。普通升级保留自己的配对、账号 Pet 和会话设置。Core 与完整版使用相同 Codex 插件 ID；要使用更多角色，用完整版升级同一插件。

## 手动蓝牙更新：需要电脑插件与设备协议匹配

支持手动更新请求的新固件，需要本次新版电脑插件。只更新设备而保留旧插件，不能获得新的手动蓝牙流程。新版插件同时兼容旧设备 v1 的原有自动下载／暂存协议；旧设备不会因为更新插件而自动出现新的设备界面。

1. 在兼容设备上点击检查更新。电脑立即处理这条手动请求，不等待六小时自动检查间隔；此时只检查版本和公告，不下载固件镜像。
2. 在设备查看候选版本，确认后电脑仅下载你确认的那个版本。目录出现更新版本时不会静默替换目标；原目标不可获取时报告失败。
3. 电脑下载时持续回报进度，再利用已认证蓝牙连接发送镜像。供电与完整性检查仍由设备执行，暂存成功和最终安装分别确认。
4. 请求被取消、替换或连接重新建立时，旧请求结果不能用于新请求。短暂重连可以复用经过验证的有限版本信息，但不跳过校验或授权。

电脑的 HTTP 下载在线程中执行，蓝牙写入仍由原桥接循环串行调度。该设计旨在保持状态同步，但主机模拟测试不能代替实际设备流畅度与升级验收。

设备 SD 安装盘中的离线包可能较旧，本次不重建或替换安装盘。离线安装后需要联网升级电脑插件，并核对共享桥接服务正在使用新版目录。

## 自动更新流程

下列能力需要设备固件支持认证、暂存和安装调度协议；老固件或未配对设备不会因安装插件而自动获得这些能力。

1. 桥接器从认证连接读取设备版本和更新能力。正常检查间隔约六小时，暂时失败安排重试。
2. 电脑从固定官方 HTTPS 入口检查已发布版本，验证签名、型号、布局、版本、长度及整包 SHA-256 后缓存文件；再次使用缓存时重新校验。
3. 设备支持时，经既有蓝牙连接传输到设备备用区域。状态和待答消息继续服务；语音、供电条件或通信错误可以中止传输。
4. 设备核对完整镜像并决定安装时间。暂存完成不等于立即安装，缺少可靠空闲依据时继续等待。

安装包只内置**验签公钥**。设备配对密钥由接收者自己的配对流程获得，不随仓库或 ZIP 分发；使用者不需要作者的签名私钥。

## 空闲依据与安装时机

兼容设备通常要求主表盘保持空闲约五分钟，并满足供电、暂存完整性等条件；新任务、待答和用户操作会影响计时。具体条件与设置由已安装设备固件决定。

本次可靠活动核查面向**本机 Codex Desktop**，结合新鲜 Hook、独立运行状态、完整本地会话目录及问题状态。目录变化、状态缺失或观察过期不当作“肯定空闲”。活跃期间不额外读取历史；冷会话核查每轮有数量限制。

这不是 Claude、Cursor、远程会话或独立 CLI 的全局活跃性证明。Claude／Cursor 的单独 Hub 不启动 Codex 轮询；没有受支持的完整空闲证据时，不会据此自动安装。混合软件使用时，不能把“Codex 空闲”理解为“所有 AI 软件都空闲”。

## 蓝牙与 Wi-Fi

既定设备策略是蓝牙可用时优先蓝牙，Wi-Fi 作为回退。无线回退、断点恢复、升级期间暂停／恢复蓝牙和安装保护由兼容设备固件负责。v0.5.4 的控制台可以在用户明确提交后，通过已认证蓝牙连接传送加密 Wi-Fi 配置；远程服务仍需单独部署或注册。

本版包含电脑的蓝牙更新客户端、配网控制台和设备局域网 HTTPS 网关，不包含完整宠物网页预览应用、设备固件、Cloudflare 服务端或部署凭据。已有远程连接服务独立管理。

## 怎样确认成功

- **下载完成**：电脑取得并验证了镜像。
- **已暂存**：设备确认备用镜像已校验，当前可能仍运行旧版。
- **已安装**：设备启动到新版本，并完成自身健康确认。

ZIP 构建成功、发送结束或 Hub 在线均不能证明设备已安装；需核对设备更新页或经过认证的版本信息。没有 SD 卡／缓存损坏时的恢复能力以设备固件为准。插件不会擦除 SD 资源、写入 eFuse 或绕过签名检查。

本次手动请求补丁提供确定性打包与隔离主机回归；没有据此声称新固件手动流程已完成实体设备验收。接收者的宿主加载、真实 Hook、蓝牙连通和设备升级仍需分别核对。
