# Windows 原生安装、绑定与连接诊断

适用：Windows 10 / 11 x64、原生 Codex Desktop / CLI、带 BLE 的电脑。
本流程对应 Codex 插件 **0.6.0**。Windows 原生包与插件源码 ZIP 是两种不同的包。
原生包包含 Python、Bleak/WinRT、串口与加密依赖，不要求 WSL，也不要求另装 Python。
本版不修改 ESP32 固件、Wi-Fi、eFuse 或 SD 卡资源。

## 一次安装

1. 下载 `Snowball-Windows-x64.zip`，完整解压。保留 `Snowball.exe`、
   `SnowballCLI.exe`、`_internal/` 和 `WINDOWS-BUNDLE.json` 的相对位置。
2. 打开 `Snowball.exe`，选择 **安装到这台电脑**。程序先验证完整包，再安装到
   `%LOCALAPPDATA%\SnowballCompanion\app-0.6.0\`，并创建当前用户的开始菜单快捷方式。
   不写系统 PATH、不要求管理员权限。
3. 向导会重新打开固定安装目录中的程序。在 **连接 Codex** 中选择 Codex 自带的
   `codex.exe`（可点击 **自动查找已安装的 Codex**），点 **安装 / 更新 Codex 插件**。它使用 Codex 官方的
   `plugin marketplace add` 与 `plugin add` 命令，并验证插件注册结果。
4. 在 Codex 的 `/hooks` 中审阅 Snowball Hooks。安装器不会自动批准或修改信任。
   安装成功和 Hooks 已获准是两个独立状态。按 Codex 的提示完成加载后，新开聊天使用。

如果安装目录中的文件丢失或损坏，先停止后台，再从**同版本完整 ZIP**打开向导，选择 **修复损坏的安装**。修复会先取得后台生命周期锁，不执行损坏的旧 EXE；旧目录隔离保留，配对和配置不删除。后台尚在运行时会拒绝修复。

如果 CLI 不支持 `plugin` 命令，向导会在注册前停止。请升级 Codex 或选择其自带的
CLI，不要选择 `Codex.exe` 桌面主程序，也不要通过 WSL 执行这个 Windows 流程。
首次 Windows 版本没有开发者代码签名证书；文件清单用于完整性校验，不能代替签名。
若被组织策略阻止，交由管理员核验来源，不需要关闭系统安全防护。

## 首次绑定：USB 一次，日常蓝牙

1. 用 USB **数据线**连接雪球，在设备上打开 **设置 → 连接电脑 / 开始配对**。
2. 向导进入 **绑定雪球**，刷新并选择对应 COM 口。多个串口时必须显式选择，
   程序不会按扫描顺序自动认领设备。
3. 点 **绑定并验证蓝牙**。向导只发送 `:PAIR` 读取设备身份，随后通过 BLE 读取
   INFO 并验证设备的 HMAC。若 Windows 弹出配对提示，核对设备名称后允许。
4. 两步均成功才保存配置；超时、选错设备或认证失败都保留原有绑定。
5. 在 **后台运行** 中启动服务，可勾选 **登录 Windows 后自动启动**。

Windows 蓝牙设置中的“已配对”不等于 Snowball 应用已认证。首次绑定要拿到当前
设备的应用密钥；重置手表后身份会变化，需要重新执行绑定。更换 Codex 账号本身不
改变设备密钥；换一台电脑需要在新电脑上绑定，不能复制另一台机器的加密文件。

**完成后可拔掉 USB。** 日常同步不需要同时连接串口，不需要每次让 Codex 代为
执行命令。电脑保持登录、蓝牙开启，Snowball 后台继续运行即可。
设备重新连接时依然校验身份，连接失败会按退避策略重试。

## 后台运行的生命周期

后台是当前登录用户的 Hub 与 BLE 子进程，不是 Session 0 的 Windows 系统服务。
向导关闭不终止后台；登录启动项使用 Task Scheduler 的 InteractiveToken 与最低权限，
不保存 Windows 登录密码、不要求管理员权限。

- **暂时停止后台**：停止本安装管理的进程，保留登录自启动设置和全部配置。
- **关闭登录自启动**：移除本安装拥有的启动任务，不停止当前同步。
- **退出登录 / 电脑睡眠**：同步暂时不可用；重新登录后按设置恢复。
- **升级**：先校验完整新包，通过经过校验的旧 CLI 停止旧后台和撤销其启动项，
  再切换安装。失败时保留旧目录与凭据，并尝试恢复原来的启动偏好。
- 多次打开向导不会启动多套 Hub 或 BLE 连接。程序校验进程创建时间、用户与会话，
  不会仅凭一个旧 PID 去结束其他程序。

首次安装或升级后，请从开始菜单打开固定安装版。向导拒绝从临时下载目录注册插件
或创建后台启动项，避免之后删除下载文件导致同步失效。

## 连接诊断

**读取连接诊断**是只读检查；**主动验证蓝牙**会暂时停止已确认归属的后台，检查
GATT 与 HMAC，然后恢复原先运行的后台。不会自动删除 Windows 的配对记录。

| 层级 | 能证明什么 | 常见处理 |
| --- | --- | --- |
| 插件注册记录 | 此安装器上一次注册是否成功；不代表现在已获 Hook 信任 | 在 Codex 插件页核对，再审阅 `/hooks` |
| 最近真实 Hook | 有事件成功送达 Hub，而不只是配置文件存在 | 自己在 Codex 发起任务后刷新诊断 |
| Hub | 本机带认证的 Hub 健康检查通过 | 在后台页启动；端口被占用时不强行杀进程 |
| 蓝牙适配器 | BLE 后端是否可用、无线电是否开启 | 开启蓝牙，检查 Windows 蓝牙驱动 |
| 应用绑定 | 当前用户能解密并验证本机保存的绑定 | 首次使用或手表重置后重新绑定 |
| 后台进程 | 属于本用户、本会话、本安装的后台是否在运行 | 从开始菜单打开已安装版后启动 |
| 蓝牙认证 / 设备回执 | 已验证设备身份，以及是否收到实际状态写入回执 | 身份不匹配需重新绑定；超时不能直接认定设备被占用 |

错误会区分未绑定、凭据无法解密、蓝牙未开启、设备没广播、后台已有连接、GATT
错误、身份认证失败和操作超时。超时可能由距离、无线电、Windows 配对提示或另一
台电脑连接引起，不能笼统标成“占用”。可在设备连接页面开启公开配对广播后重试。

**导出脱敏诊断报告**只输出固定错误分类、版本、健康状态和时间信息，不包含
Windows 用户名 / 绝对路径、设备地址、配对密钥、原始异常、问题内容或会话正文。
不要把私有原始日志、`ble-pairing.json` 或整个用户配置目录上传到公共 issue。

## Windows 的功能边界

本版完成原生安装、后台与登录启动、首次绑定，以及 Codex Hooks → Hub → BLE
的状态通道。会话目录遵循当前 `CODEX_HOME`，未配置时使用当前用户的 `.codex`。

Linux 的 Desktop 私有 IPC 不能直接用于 Windows。因此 **从手表回复问题、发起新
会话、向现有会话发送指令**在本 Windows 版明确标为尚不支持，不会显示为已发送。
缺乏完整活动覆盖时，自动空闲安装保持保守判定，不能将未知活动当作安全空闲。
Claude / Cursor 的既有适配器没有在本轮宣称完成 Windows 原生迁移。

## 卸载与凭据

只卸载 Codex 适配器：使用 Codex 插件管理器，或在已核对支持的 CLI 中执行：

```powershell
codex plugin remove xueqiu-status@xueqiu-local --json
```

若同时不再使用 Windows 后台，在向导里依次 **关闭登录自启动**、**暂时停止后台**，
确认诊断显示停止后关闭向导，再删除已确认属于 Snowball 的版本安装目录与开始菜单
快捷方式。不要删除别的适配器正在使用的共享目录，也不要直接删除整个 `.config`。
配对配置在当前用户的 `.config\xueqiu\` 下，Windows 使用当前用户作用域的 DPAPI
加密并限制文件 ACL；状态与私有日志在 `.local\state\xueqiu\` 下。
普通卸载保留它们，也保留账号 Pet、设备固件和 SD 卡内容。

## 构建与验证

维护者在原生 Windows x64 上使用 `tools/windows/build.ps1` 构建。
CI 使用临时普通用户运行 Windows 锁、ACL、DPAPI、运行层及向导测试，并检查双
EXE、GUI 启动和包含中文路径/内容的 Hook。构建过程只取公开 Codex bundle 白名单。
Linux 单元测试、Windows CI、真实 Windows 蓝牙设备验收是三个不同层级；
通过前两个不能写成第三个已完成。具体结果见对应 CI 运行和交付说明。

参考：[Codex Hooks 的 Windows 命令覆盖与信任](https://learn.chatgpt.com/docs/hooks)、
[Windows 登录任务的安全上下文](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks)、
[Bleak Windows 后端](https://bleak.readthedocs.io/en/latest/backends/windows.html)。

账号桌宠仍通过插件 Setup 与宿主 Pets 服务安装／切换。Windows 不需要为随包辅助脚本另装 Python：安装目录中的 `SnowballCLI.exe pet --help`、`SnowballCLI.exe pet list` 可运行 Pet 辅助入口；创建账号 Pet 仍需当前账号授权及实际服务核验。

如果 CI 的 Windows Job 明确禁止分离后台进程，生产入口会返回 `host_job_restricted`，不会静默改为随终端退出的子进程。CI 仅在核实这一错误后，使用已有 `runtime run` 前台模式留在同一 Job 内验证后台与任务计划；报告明确区分此模式和真正的独立后台启动。普通桌面从开始菜单启动后的独立寿命，以及实体蓝牙连接，仍需真实用户桌面验收。
