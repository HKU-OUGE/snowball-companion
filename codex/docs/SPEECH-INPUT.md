# 语音输入 · 原生 0.17.0

雪球负责录音和确认，电脑插件负责本地转写。可向已存在的本机 Codex 聊天发送新指令，也可给对应的异步待答问题发送自由回答。0.17.0 会话列表包含空闲聊天，底部「创建新会话」支持确认后建立独立聊天，详见 [会话与任务](SIDEBAR-TASKS.md)。Claude / Cursor 的状态显示继续保留；本版没有实现它们的语音消息投递。

## 设备操作

1. 从表盘进入会话详情，选择“布置任务”（运行中为“追加指令”）；也可在待答详情的“选择答案或语音”中选择“语音回答”。
2. 看清目标会话后点“开始录音”，说完点“说完了”；最长 20 秒会自动停止。
3. 电脑识别后，设备显示可上下滚动的识别文字。文字正确时点“确认发送”，否则点“重新录音”。
4. 只有电脑确认接收后才显示“已送达会话”。如果显示“送达未确认，请看电脑”，不要把它当成失败后自动重复发送。

录音开始后目标会话和问题固定。后台自动关注另一个聊天不会改变这次语音的收件会话。离开录音页面会停止录音；录音、传输和检查文字期间保持亮屏。录音期间暂停扬声器提示，以免提示音进入录音，其他状态更新仍继续。

本版发送的是转写后的文本，用户录音不上传到语音云服务。Codex 会正常处理用户确认发送的文字。权限批准仍走软件原有流程；语音功能不直接调用权限批准接口。现有 Desktop 异步问题框在外部回答后未自动收起的限制仍然存在，见 `DESKTOP-QUESTION-UI.md`。

## 网页

本地预览的“会话 → 本机会话 → 会话详情 → 布置任务”和“待答 → 选择答案或语音 → 语音回答”使用同一个本地识别服务。浏览器首次录音需要麦克风权限。网页可编辑识别文字后再确认发送，也可点击「输入文字」而不使用麦克风。

网页录的是电脑选定的麦克风；设备入口录的是雪球麦克风。离开页面后释放浏览器麦克风和音频上下文。独立静态网页没有本机语音服务，不会假装已录音或已发送。

## 插件电脑端

新增 `desktop/speech_service.py`、`speech_relay.py`、`setup-speech.py`；分发插件中对应 `companion/`。初次配置运行：

```sh
python3 companion/setup-speech.py
```

安装器创建独立的 `~/.cache/xueqiu/speech-venv`，下载固定版本的多语言 `Systran/faster-whisper-small`，将路径保存至私有的 `~/.config/xueqiu/speech.json`。模型缓存位于 `~/.cache/xueqiu/speech-models`。识别用 CPU int8，最多 8 个 CPU 线程；运行时只读本地模型，不需要 OpenAI API 密钥。首次安装需要联网，之后转写可离线执行。

默认自动判断输入语言，并将中文字符转换成简体。模型与 Python 依赖不塞入固件或 SD 卡。安装完成后，电脑 BLE 桥接器会按配置启动语音服务。服务监听 `127.0.0.1:4191`，使用已有私有 Hub token；网页服务器代理请求，不把 token 暴露给浏览器。端口不对局域网开放。

开发和当前运行验证在本机 Linux 完成。依赖安装脚本保留通用路径处理，但 Windows/macOS 的设备接入没有在本版完成实机验证。

## 录音、传输和节电

- ES8311 模拟麦克风，I2S DIN 为 GPIO18，控制总线仍使用厂商 BSP。
- 音频 worker 独占 codec；录音时切换输入模式，结束后回到 TX-only 并关闭 codec / RX。没有常开录音或唤醒词检测。
- 48 kHz 双槽输入经每 3 个左声道样本平均降到 16 kHz 单声道，编码为高半字节优先的 IMA ADPCM；上限 160,000 字节 / 20 秒，存 PSRAM。
- BLE 新增 `9e7a0005-6ed4-4b6b-bf37-43dc42838c20`。加密链路、启动 nonce 和 HMAC 验证元数据与通知块；通知窗口有界，缺块可重取，完整 CRC 校验通过后才送本地识别。
- 控制消息 v8 与原有状态写入共用单个发送者及序号，转写在异步任务执行，保持状态、问题和电量心跳。
- 空闲语音轮询约 2 秒一次；传输时暂时提高读取频率。录音码流和转写内容不写入普通日志，也不默认写入 SD 卡或录音历史。
- 新增回调避免在蓝牙任务栈上复制完整转写；NimBLE host 栈由 4096 调为 6144 字节。首次测试暴露的栈溢出已经修复，修复后实机元数据读取测到约 2596 字节栈余量。

### 0.15.2 上传提速

语音元数据 v3 支持每批最多 96 个带认证的音频块；老 v1/v2 固件仍使用 24 块。上传时减少重复状态读取，把角色目录、会话长摘要等批量同步暂缓最多 8 秒，仍持续处理新状态、待答提醒和电量。识别结果和发送回执也优先于批量同步。

设备首次收到认证的上传请求时临时请求更短的 BLE 连接间隔。实测从 50 ms 切换到 15 ms，上传 CRC 校验完成后恢复 50 ms，两个参数更新均返回成功。10 秒无续期也会恢复；断线不会保留高频租约。该检查证明本次连接参数已恢复，不等于完成了新一轮续航测试。

界面将等待拆成“正在上传录音（百分比）”和“电脑正在识别”。空闲、失败和已送达页面可以按原设置息屏；正在录音、上传、识别、检查文字和发送时保持亮屏。

三轮真人录音长度相近、内容不同，不是同一音频的严格性能基准：

| 固件 | 录音长度 | 上传耗时 | 模型识别耗时 |
|---|---:|---:|---:|
| 0.15.0 | 5.50 秒 | 34.799 秒 | 2.583 秒 |
| 0.15.1 | 5.60 秒 | 11.079 秒 | 2.528 秒 |
| 0.15.2 | 5.66 秒 | 2.236 秒 | 2.468 秒 |

最新一次从电脑记录上传开始到向设备提交文字结果为 5.513 秒，用户反馈“5 秒以内”。上传耗时取同一计时字段，包含前置元数据读取，因此不能与日志事件时间差简单相加。它也不是从物理按键到屏幕出现文字的精确测量。

## 确认与去重

创建独立聊天使用 `/v1/session/create`；新指令使用 `/v1/message`；问题回答继续使用 `/v1/answer`，带准确的问题 identity。必须先在界面确认；没有自动发送、语音触发批准、按关键词直接执行 shell 的路径。

Hub 在投递前持久化 request ID 和文本摘要哈希，不保存另一份回答正文。已接收、投递中和投递结果未知的请求不自动重放。既有聊天优先通过安装中的应用工具投递，未加载的本机聊天也可接收。仅在该工具不可用且尚未尝试投递时使用旧的已有聊天 IPC；不会在一次投递结果未知后切换路径重发，更不会另开一个聊天代发。

## 验证边界

软件验证包括：固件编译、真实 C ADPCM 编码器与标准解码格式对齐、签名与启动 nonce、缺块/乱序/重复块、目标会话与问题绑定、已确认消息的去重、网页真实麦克风 API 流程（测试使用假麦克风，拦截投递）。

软件截图是 LVGL 重绘，不是物理屏幕照片；网页测试没有向真实聊天发送测试文本。真实收音、真实语音送达和人类识别质量反馈分别记录在当前版本 QA 中，未通过的项目不能从编译或截图推断。

0.15.0 修复 BlueZ 回显后，用户确认识别文字正确，并在设备确认发送；真实新指令已到达当前 Codex 聊天。0.15.1 的真实语音回答也已到达，但包含会话快照的回执超过原来的 64 KiB 上限，设备错误提示“送达未确认”；0.15.2 将 Hub 回执上限独立设为 1 MiB，识别服务响应仍限制 64 KiB。

0.15.2 已通过 196 项原生/电脑端回归、固件构建和 app1 写入哈希验证。网页对应版本此前通过 135 项逻辑测试、4 项 Sites 测试、构建/导出和假麦克风浏览器操作检查，本次仅更新电脑桥接和设备固件，未重复声明新的网页硬件验证。

最新提速试录已成功返回文字，但随后“确认发送”未取得成功回执，对应问题当前已不再待答，Hub 中也没有本次发送成功记录。旧日志没有保存 HTTP 状态，不能确定当时拒绝的具体分支，未尝试重发。已补充确定性的 HTTP 409 目标失效提示与回归测试，后续不会把这类拒绝误报为识别服务故障。未知投递仍提示到电脑核对，不自动重试。

## 故障提示与日志

设备区分麦克风启动失败、录音太短、没有人声、语音服务忙、传输失败、会话变化、电脑识别失败和送达未确认。网页同步显示本地识别服务的具体失败类别。

电脑 `~/.local/state/xueqiu/bridge.log` 的 `speech` 事件记录上传开始、字节数、CRC 通过、识别/送达阶段及耗时；`speech/service.log` 记录录音时长、RMS、峰值、直流偏移和识别是否成功。串口记录左右输入槽的 RMS。诊断只保留数值和状态，不写入录音或转写正文。

断开后可以重新拉取尚未确认的完整录音；电脑进程重启后若丢失已检查的文字或发送回执，会明确提示返回重录或到电脑核对，不自动重发。分块接收窗口以请求时的偏移计数，避免通知在写入回执前到达导致额外等待。

### Linux BlueZ 状态读取回显修复

语音特征同时支持 read 与 notify。在本机 BlueZ/Bleak 上，`ReadValue` 更新特征值时也触发通知回调；因此上传中读取状态，会把签名 JSON 元数据交给音频收集器。此前收集器只接受 `XQVC` 音频块，误报损坏并停止上传。

接收器现在先区分两种消息：JSON 仍须通过完整元数据 schema、HMAC 与启动 nonce 校验，验证后忽略读回显；`XQVC` 继续按原有块签名、范围、重复数据与最终 CRC 校验。没有放宽音频校验。

真实设备连续读取三次，复现了三个 216 字节的状态通知；修复后三次均通过签名验证且不进入音频缓冲区。回归测试同时覆盖读回显和伪造元数据拒绝。此项修复在电脑桥接器完成；后续上传进度、临时连接加速和字库扩展已随 0.15.2 固件更新。

## 动态问题与摘要字库

核对近期问题内容，确认旧字库缺少 `→`。0.15.2 将动态文字使用的 `ui_font18b` 从 6,912 个字形扩为 9,860 个，保留全部 6,763 个 GB2312 汉字，并补充字体源实际支持的箭头、数学符号、常见标点、希腊字母、假名与全角符号。常用勾选、警告、表情和爱心使用可读的单色字形；emoji 变体选择符不占位、不再显示方框。

真实设备字形查询对 `→ ≤ ✅ ⚠️ ❌ 汉 字 🙂` 通过。测试检查实际生成的字库覆盖，未用替换问题正文的方式隐藏缺字。该字库不是全 Unicode：罕见汉字、部分 emoji 和复杂组合仍可能不支持。当前 0.15.3 app1 剩余 46,736 字节，后续大幅扩字或加入本地识别模型前需要重新规划资源；本版没有改分区或把新字体加载器引入 SD 卡。

## 0.15.3 阅读布局修正

0.15.2 字库扩充后，少数符号把统一行高撑到 34 像素，导致既有固定布局拥挤。0.15.3 在生成器中将这些特殊字形适配到原来的 22 像素行框，不直接裁掉笔画；普通汉字与 ASCII 位图不变，9,860 个字形保留。

选项卡片改为按完整文字计算高度并换行，不再用省略号隐藏末尾。选项列表、确认页及会话摘要支持上下阅读，设备有可见滚动条；网页支持鼠标拖动与触摸，并阻止拖动结束时误点。点击选项仍只进入确认页。会话页删除常驻“拖动右侧…”说明，排序草稿通过“保存并返回”操作保持可见，失败提示与列表/按钮分开。

## ESP32 本地识别的范围

ESP-SR MultiNet 可在 ESP32-S3 上做中文、英文的预设命令词识别，适合“返回”“开始录音”“选第一项”等。它不能直接替代本版任意长句的听写。当前仍由电脑本地模型处理自由指令与自由回答，未安装常开唤醒词或 MultiNet 模型；SD 卡扩容也不会增加芯片的运算能力。
