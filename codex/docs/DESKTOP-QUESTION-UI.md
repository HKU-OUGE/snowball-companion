# Desktop 问题框未收起：已确认的兼容限制

2026-10-19，用户在设备上明确选择并确认后，原问题的结构化回答已到达原 Codex 聊天，电脑投递回执为 accepted，Hook / Hub 的原问题和回传路由均移除。但用户确认 Desktop 上的问题输入框仍然显示。消息投递与问题框关闭是两个独立的验收项目；前者通过，后者未通过。

## 当前版本的原因

只读检查本机 `/usr/lib/chatgpt/resources/app.asar`，未改动安装文件或窗口：

- 前端的历史刷新函数 `LIt` 更新问题的 lastSubmission 和未修改的草稿，但其 composer 列表只移除已经不在原回合中的问题，并不因为收到回答而自动收起。
- Desktop 本地提交回调 `k$e` 另外完成问题输入状态更新；只有这条回调才从当前 composer 中移除刚提交且草稿一致的问题。
- 现用版本化线程 IPC 的 start / steer 方法回传消息结果，没有 async 问题输入框的收起接口。阻塞式 user-input / permission approval 接口不是这类异步问题的替代品。
- 若原问题与回答跨回合，原回合的答案索引还有单回合范围限制；补充一个 turnTrigger 字段不能代替本地提交回调。

隔离运行安装版本的上述两个函数，使用模拟状态依赖：外部历史更新识别回答并更新空白草稿后，composer 仍存在；运行本地提交结束回调后，composer 才关闭。结果及源文件哈希见 [检查记录](../qa/v0.13.0/desktop-question-ui-audit.json)。这是源码与隔离复现证据，不是对正在运行窗口的修复或视觉验收。

## 使用与后续修复边界

答案送达后不要重新发送，也不要自动回复空文本、伪造历史通知、重新启动会话或替用户跳过其他问题。单条已回答的问题框可由用户手动点「跳过」收起。多问题表单可能含有其他草稿，不能整体清除。

可靠的自动同步需要 Desktop 提供按 thread / question identity 结束问题输入的接口，或在前端收到外部结构化回答时，对匹配的问题执行与本地提交一致的状态收敛。应覆盖跨回合回答、同一表单中的其他未答问题、用户已经编辑的新草稿和重复投递；既有 accepted 回执不得用于补发。

本轮没有修改 Codex 安装包，没有自动操作 Desktop 问题框，没有重发答案，没有更改 ESP32 固件。此限制仍未修复。
