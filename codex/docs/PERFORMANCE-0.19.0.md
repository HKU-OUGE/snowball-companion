# 详情复用与切页绘制 · 0.19.0

已安装到测试板的app1。详情页首次创建控件后保留，后续只更新名称、状态、摘要、按钮及其目标。相同会话的摘要更新保留阅读位置；不同会话从顶部开始。列表详情与主表盘详情分别绑定正确的返回入口，任务输入继续使用已展示的会话身份。

切页保留原来的180毫秒ease-out与14像素位移。过渡时将静态内容绘入一块共享RGB565画面，裁掉黑色边缘，仅移动实际控件和有效画面，不反复重画360×360空白根节点。雪球、眼部、星星与旋转状态图标继续实时动画。触摸、新状态、切页中断和角色交换先撤除临时画面；最后一帧完成后恢复真实控件。缓存分配失败自动使用原绘制方式。仅分配一块259,200字节PSRAM画面，不为每个页面累积整屏图片。

## 与0.18.3同方法实机对照

正常生产蓝牙连接，六轮设置→表盘→会话→表盘→详情→表盘，共36次切页；均处于执行中状态。页面先预热，计时窗口内不截图、不注入任务状态。下表为每次切页最大单次LVGL绘制时间的中位数，**不是触摸到可见延迟或物理FPS**。

| 目标 | 优化前 | 0.19.0 | 降低 |
|---|---:|---:|---:|
| 设置 | 86.819ms | 64.882ms | 25.3% |
| 会话列表 | 97.576ms | 74.068ms | 24.1% |
| 详情 | 90.840ms | 66.289ms | 27.0% |
| 返回表盘 | 80.565ms | 73.103ms | 9.3% |

重复进入详情的重建耗时由46.109ms降为0；36次温热页面切换均无重建、无缓存分配回退，结束后临时画面均释放绑定。

缓存准备本身仍有开销：设置33.495ms、会话44.124ms、详情38.594ms、表盘26.418ms（各窗口中位数）。将其计入窗口内绘制与准备工作，四组总耗时分别降低14.3%、10.3%、22.7%、10.4%。窗口还包含过渡结束后的静止或宠物动画；不能把总和当作切页动画时长。首次打开页面仍会创建控件，未宣称消除所有卡顿。

约8.2秒的稳态检查：表盘249次更新、68次宠物帧变化，与之前一致，约30.3Hz；静止设置和息屏颜色呼吸均为0次画面重绘。CPU、屏幕传输频率及sdkconfig未改变。本轮没有重新测量完整续航。

## 回归与复用

设置、会话、详情的正常绘制与缓存绘制通过实际LVGL输出条带逐像素比较，差异为0；表盘静态区域也为0，宠物与旋转图标区域因继续动画而不同。软件条带采集不是面板照片。

九项实机详情检查通过：已有会话输入、无会话创建入口、摘要右滑返回、运行详情、摘要更新保留滚动且不重建、另一会话任务入口、关注变化时保持已查看目标、列表返回、主表盘返回。三个生产代码host测试组覆盖控件生命周期、语音任务目标绑定与临时画面失败/中断/位置恢复；四组控制器检查和完整教程回放通过。实机使用USB指针进入正常LVGL流程，未录音、未创建会话或发送任务。最终恢复教程进度、显示设置、原设置页与生产蓝牙同步。
