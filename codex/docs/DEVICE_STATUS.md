# Snowball Companion · 设备状态同步与历史记录

通过 Codex 生命周期 Hooks，把工作阶段和当前会话名称发送给本机雪球状态服务，再经 BLE 显示到圆屏伴侣。会话名称是用户授权显示的元数据；插件还发送匿名会话标识、状态、序号与时间，仅额外发送用户授权的显式提问标题；不发送答案、对话历史、源码或其他工具正文。插件不处理权限批准。

## 安装与升级

**先把圆屏伴侣更新到雪球原生固件 0.4，再更新并启动此包的 Hub 和 BLE 桥接。** 新桥接会传输会话名称；旧固件不支持相应协议。插件与 companion 应使用同一发布包，不要混用旧版组件。

将整个文件夹放到固定位置，运行：

```sh
./install.sh
```

安装器通过官方 Codex 命令注册 `xueqiu-local` 本地市场，并安装 `xueqiu-status@xueqiu-local`。需要 Python 3 和 Codex CLI。移动市场文件夹后应重新注册路径。

升级前，安装器会将这个插件已有版本的 `scripts/` 和 `hooks/` 原文件、权限及 SHA-256 清单保存到私有目录：

```text
~/.local/state/xueqiu/plugin-upgrade-backups/<UTC时间-随机后缀>/
```

遵循 `XDG_STATE_HOME` 与 `CODEX_HOME` 自定义目录。备份目录权限为 `0700`，备份文件为 `0600`，不会收集 token、配对密钥或对话。官方安装命令可能清理旧版本缓存，所以同一个外层进程会在安装命令结束后恢复缺失的旧脚本和 Hook 定义；安装失败、正常的 Ctrl+C 或 SIGTERM 也会执行恢复。已有文件不会被覆盖，其他插件及 Hook 信任记录不会被修改。备份和兼容文件会保留，不自动清理，以便仍运行中的 Desktop 会话继续调用原来审阅过的路径。断电或 SIGKILL 无法保证执行恢复，备份仍可用于手动恢复。

**安装后完整退出并重启 Codex Desktop，再开始新任务。** 兼容文件只保障旧会话能继续结束或执行修复；它们不代表旧进程已切换到新版功能。首次安装、版本变化或 Hook 定义变化时，在 Codex `/hooks` 中审阅实际命令并按提示信任。安装器不会跳过审阅，也不会手动写入信任记录。

安装器的离线回归测试不接触本机配置：

```sh
python3 tools/test_install_plugin.py
```

## 本机后台服务

插件依赖同一电脑的状态 Hub 和 BLE 桥接。此包附带 companion 工具。升级已有后台组件时，先用旧组件对应的管理命令停止它们，再在固定位置更新 companion 文件并启动新组件；不要重复启动第二套服务。

```sh
python3 companion/manage_hub.py start
./companion/connect-bluetooth.sh start --source "$HOME/.local/state/xueqiu/hub/snapshot.json"
```

首次绑定自己的圆屏伴侣使用 `./companion/connect-bluetooth.sh pair-usb --port /dev/ttyACM0`。已配对的设备无需重复绑定。Hub token 与 BLE 密钥生成、保存在用户私有目录，不随插件分发。此安装不设置开机自启。

## 会话名称与状态语义

0.2.0 在 Hooks 未提供名称时，使用事件中的精确会话 ID，只读查询本机 Codex 已知状态数据库的 `threads.name（旧schema仅有title列时使用title）`。不读取对话、首条用户消息或记录文件；查不到名称时保持未知，不伪造任务名。这是可选的本机元数据适配，数据库结构变化时可能暂时无法显示名称。详细字段和协议见 [SESSION-METADATA.md](companion/SESSION-METADATA.md)。

支持提交输入、工具执行、等待确认、本轮停止、会话开始/结束、压缩上下文和中断。“本轮完成”不代表项目成功；普通工具失败不直接判断整轮失败。Hooks 事件有效期 300 秒，没有新事件时进入待同步。BLE 每 5 秒刷新有效状态，过期后只读探测，不伪造 AI 活动。

## 停用

```sh
codex plugin remove xueqiu-status@xueqiu-local
```

停用插件不自动停止 Hub 或 BLE，以免影响其他软件适配器。需要时分别运行 `./companion/connect-bluetooth.sh stop` 与 `python3 companion/manage_hub.py stop`。在运行中的 Desktop 会话停止引用旧版插件之前，不要手动删除旧缓存兼容文件。

早期版本安装与信任记录不代表另一台电脑已安装或新版已信任。新版实际安装和真实任务验收须在目标电脑执行；离线安装器测试不等于 Desktop 或硬件验收。

## 0.9 会话优先级列表

上滑进入当前软件的会话列表。右侧手柄上下拖动，松手后经蓝牙确认保存；圆屏伴侣把首/末行拖到列表上/下边缘可跨页移动。网页另有上下按钮和键盘方向键。排序后自动进入“按顺序关注”；点会话正文仍可明确固定关注，再点底部按钮恢复自动。

自动模式依次选择：当前异常 > 等你回答/确认 > 思考/执行。同类按用户列表顺序；完成或空闲让出显示，恢复运行按原顺序归队；全部安静时显示最近的完成/空闲。过期运行/错误不会当作实时活动；尚未回答的问题继续保留待答。优先级按软件独立，软件仍在设置里切换。圆屏伴侣每次同步最多8条会话，优先包含活动会话；分页每页3条。完成/空闲在新鲜期内仍可见并可排序，过期记录退出显示但电脑端保留顺序，恢复更新后按原位置参与。

电脑端顺序保存在私有hub/sessions.json，重连或重启不会重新按消息时间排序。网页使用模拟数据并保存在浏览器，网页排序不直接操作真实电脑任务。拖动保持行身份稳定，拒绝列表成员/顺序改变、过期、签名篡改或旧请求，心跳不影响排序；排序ACK前不声称保存成功。

协议：catalog_v=2，逆向请求附action(0关注/1移动)与before(目标前插，空为末尾)，HMAC覆盖原34字节+action1字节+before16字节。电脑兼容旧v1关注请求；移动通过现有授权/v1/focus接口的provider/move/before字段保存，无需发送或保存会话正文。启用自动列表后，圆屏伴侣依照电脑端返回的当前会话显示，新的优先待答/异常仍能触发声音和息屏提醒。红黄1秒闪烁、绿灯1.5秒呼吸及完成常亮保持不变。

## 0.9.1 列表草稿、退出保存与翻页

本节取代0.9每次拖动即保存的行为。紧凑会话标题固定单行，以省略号截断，完整名称仍可在详情阅读。列表右侧上下箭头翻页；调整顺序只修改草稿，多次拖动/跨页不会发送排序或改变电脑端优先级。后台状态刷新和息屏/唤醒不提交草稿。

返回、下滑离开列表或点“保存并返回”时，一次提交最终顺序。等电脑确认后才离开；拒绝、过期或断连时仍留在列表并保留草稿，点“重试并返回”重试。列表成员变化时按身份合并：保留仍在列表内的草稿相对顺序，添加新会话、移除不再可用的会话。编辑中的会话行点击只保存并返回自动模式；没有编辑时仍可点选固定关注。

BLE使用catalog_v2的action2批量提交：id为空，before16字节编码[count,index0,...,indexN-1,0padding]，最多8行，是对应generation完整排列；51字节HMAC结构不变。桥接器验证签名、catalog lease、排列唯一性与成员一致性，向本机授权/v1/focus提交provider/order。Hub在同一把锁内一次写入排序并切到自动模式，未列出的会话和其他软件保留原位。网页采用同样的草稿/退出交互，但仍是浏览器模拟，不直接写电脑真实会话；本地存储失败时不丢草稿、不虚报已保存。

非对称1.5秒呼吸(400/800/300ms)、红黄1秒闪烁与亮度设置保持不变。

## 0.9.2 查看详情与明确关注模式

点击会话只打开该会话的详情，不固定关注、不改变自动选择对象。详情绑定provider+会话ID，后台自动切换不会把正在阅读的详情换成另一个会话；列表详情返回原列表页。若有排序草稿，点击会话先按原流程一次保存，再打开所选详情，仍保持自动模式。

设置→AI软件→关注方式：自动切换为默认；只有明确选择“固定当前会话”才锁定当前表盘的活动会话，页面同时显示当前名称并等待电脑确认。固定对象完成、空闲或活动证据过期后自动恢复优先级队列；未回答的问题保持待答，不被普通TTL静默抹去。列表点击在任何模式下都只查看详情。

Hub保存focus_policy_version=1，用于把旧版隐式点选固定迁移到自动，保留用户顺序。新明确固定的活动会话可跨重连/重启保留，结束即自动释放。网页队列存储升级version3，同样清除旧版意外固定并保留排序；网页仍是本地模拟，真实电脑状态通过插件/蓝牙连接圆屏伴侣。


0.12.0授权范围更新：新增用户明确要求的「提问工具的问题标题」与独立问题ID，不含答案、任意工具输出或命令。支持按问题暂缓600秒、忽略和恢复；不执行回答或批准。正常空闲由在线Hub明确报告，运行状态失效仍保留未知。详见随包 ATTENTION-DETAILS.md。
