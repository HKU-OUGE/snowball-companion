# 所有本机会话与主动布置任务 · 0.17.0

本机会话目录与任务状态分开：本机 Codex 侧边栏中未归档的用户聊天，即使目前空闲、没有新任务或尚未在窗口加载，也保留在会话列表。内部建议、审查和子代理聊天被过滤。目录导入不启动聊天、不制造运行状态、不延长旧任务的有效期。此次本机实际读取到 23 个用户聊天。

## 使用

1. 表盘向上滑动进入会话列表。右侧箭头翻页，每页三个会话；标题保持单行，长名称显示省略号。
2. 点击任意会话查看详情。空闲或已完成会话显示「布置任务」，运行会话显示「追加指令」。设备点击「开始录音」，识别后检查文字，再「确认发送」；网页也可直接输入文字。目标在进入输入页时固定，不随自动关注切换。
3. 列表底部为「创建新会话」。输入新任务并明确「确认创建」之后，才在本机 Codex 中建立独立聊天，使用应用默认设置。不会默认继承当前项目、创建工作树或复制已有聊天历史。仅打开页面不会录音、发送或创建。
4. 仍可通过列表向下滑动返回表盘。设备调整顺序后，离开列表才整批保存；底部此时显示「保存并创建」，保存成功再进入创建页。点击会话只查看详情，不改变关注模式。

网页在本地预览默认显示真实「本机会话」；原任务表盘和独立静态预览仍保留演示模式，不能据演示状态推断电脑任务。Claude、Cursor 的状态展示保持原实现，本次新增消息与创建入口仅支持本机 Codex。

## 电脑端与送达

`desktop_directory.py` 以只读方式读取当前 Codex 本地会话索引，每五秒刷新。目录行独立标记，不占用有界的任务事件缓存；陈旧状态仍显示未知，导入历史聊天不会挤掉活动任务或伪造事件。用户原有优先级保留，新发现的会话追加到末尾。

`app_tools.py` 仅允许应用的三个原生工具：读取项目、发送到指定聊天、创建聊天。通过安装中的 Codex 应用工具通道调用，校验当前用户、套接字和安装位置。没有向网页或 BLE 暴露任意工具调用接口，也不修改 Codex 程序、权限、模型或工作区设置。创建前先读取项目清单；当前界面只创建独立聊天。

`/v1/session/create` 仅接受任务文字与请求 ID；既有会话使用 `/v1/message`。Hub 保持仅回环监听和私有令牌认证，网页代理仍验证来源。收到明确确认后，先持久化请求 ID 与文字摘要哈希，再投递。相同请求不会重复创建；若结果未知，提示到电脑核对，不自动重发。新聊天或新指令的「已接收」不等于任务已经执行完毕。

设备语音的新会话意图使用保留的全零 session ID，必须同时有新鲜 Hub 与 `can_create` 授权。其余会话身份仍是原有签名绑定；录音和识别过程不能自行变更目标。

## BLE 目录与容量

原生目录容量从 8 扩到每软件 64 项，放入 PSRAM；当前 23 项全部可见。更多本机会话可在网页查看，设备仍受 64 项容量限制。会话摘要保持原有最多八项通道，优先当前关注及活动会话；历史目录项可布置任务，但可能没有已缓存的旧摘要。

INFO 紧凑格式 v5 声明目录协议 v3：目录 begin 的 bit3 为创建能力，行状态的 bit7 表示未知；操作 3 仅续目录租约，操作 4 原子更新状态、关注与回执。名字和顺序不变时不重传全部标题。长列表排序使用 action12 的 49 字节排列编码，保留完整 HMAC，最大 INFO 仍不超过 512 字节。旧固件保留原八项协议。

## 验证边界

测试覆盖 23 项空闲目录、归档/内部过滤、任务缓存已满、确定目标、确认后创建、重复请求去重、未知结果不重放、64 项原生解析与整批排序、租约续期和状态增量。桌面和手机浏览器通过模拟请求验证完整的输入、确认和分页。

实机检查包括 23 项目录的第 8 页、空闲详情、布置任务入口、创建入口、滑动返回、蓝牙同步与未开启广播，以及保留完成的教程。截图为 CRC 校验通过的 LVGL 软件重绘，不是实体面板照片。创建/发送的真实写入没有自动执行；只读项目工具已连通，首次真实任务仍由用户在输入页明确确认。未进行本版本完整续航测试。

当前实现依赖安装版本的 Codex 本地索引和原生应用工具通道；若应用升级改变格式，功能会拒绝投递并提示连接问题，不能将这条本地集成视为稳定的公开远程 API。

2026-10-22 实体显示补充：用户确认「创建新会话」页的「开始录音」和「返回」两个按钮都能看到。这两处实体显示通过核对，软件快照遗漏未修复，不扩大为所有页面的实体验收，也不代表已经执行真实创建或发送。
